# 스토어에 올릴 화면 사진 — 한국어 다섯 · 영어 다섯

> **초안 — 사람의 승인 전에는 제출하지 않는다.**

> 한 줄 요지: **여기 열 장은 스토어에 올릴 후보이고, 저장소의 다른 화면 사진들과 고르는 기준이 다르다.** 다른 폴더의 사진은 시안과 나란히 놓고 값을 대조하려고 찍은 것이고, 이 열 장은 **처음 보는 사람이 이 앱이 무엇인지 알아보게 하려고** 찍은 것이다. 그래서 자리도 크기도 따로 정했다.

## 크기 — 왜 1290×2796 인가

이 크기가 **애플이 요구하는 6.7·6.9인치 아이폰 화면 사진의 정확한 크기**다. 구글 플레이는 짧은 변 320px 이상·긴 변 3840px 이하면 받으므로 같은 사진을 그대로 쓸 수 있다. 다른 크기로 찍어 두면 제출할 때 사람이 늘리거나 잘라야 하고, 그러면 글자가 뭉개진다.

찍는 법은 `viewport` 430×932 에 화소 배율 3 이다. 430 은 이 앱이 이미 확인한 너비이기도 하다 — W1 이 320·375·390·430 네 너비에서 묵주와 기도문이 겹치지 않는 것을 사진으로 남겼다.

## 어떻게 찍나

```bash
npm run build:web && npx playwright test e2e/store-screenshots.spec.ts
```

**모두 사람이 실제로 지나는 길로 들어가 찍는다** — 첫 화면에서 홈으로, 홈의 카드를 눌러 기도로, 아래 탭 바로 여정과 갤러리로. 주소를 직접 열고 찍으면 배선이 끊겨 있어도 사진이 나오므로, 사진 자체가 "닿을 수 있다"의 증거가 되게 하려는 것이다.

성화 뽑기의 씨앗은 `screenshots.spec.ts` 와 같은 값(`20260918`)을 쓴다. 두 곳의 사진에 서로 다른 그림이 뽑히면 "같은 화면인데 왜 그림이 다른가"를 매번 되물어야 하기 때문이다.

## 제출 전에 사람이 손봐야 하는 것 넷

정직하게 적어 둔다. **지금 이대로 제출하면 안 되는 자리들이다.**

1. **갤러리 사진에 워터마크가 있는 성화가 그대로 보인다.** `*-3-gallery.png` 의 오른쪽 위 `성모와 아기`(`12-mary-child-neutral.jpg`)와 그 아래 `성모와 아기 예수`(`02-mary-child.jpg`)가 둘 다 자국이 있는 그림이다. 자국 자체는 작아 축소된 사진에서는 잘 보이지 않지만, **권리가 정리되기 전에 그림을 스토어에 올리는 것은 사진 크기와 무관한 문제**다. 어느 장에 무엇이 있는지는 [`../art-watermark-audit.md`](../art-watermark-audit.md) 에 있다.

2. **영어 사진의 기도문이 한국어다.** `en-4-pray.png` 의 기도문(`성부와 성자와 성령의 이름으로, 아멘.`)과 아래 단추의 단계 이름이 한국어로 남아 있다. **이것은 결함이 아니라 결정이다** — 확인되지 않은 기도문을 사람이 바치지 않게 하려고 화면 문구만 영어로 옮기고 바치는 말은 한국어 정본을 쓴다(결정 12-2 카드 C). 다만 영어권 스토어에 이 사진을 그대로 올리면 "영어 앱이 아닌가" 하는 오해를 부르므로, **영어 사진 다섯에서 기도 화면을 빼든지 기도문 판본이 확정된 뒤에 다시 찍든지** 사람이 정해야 한다.

3. **영어 사진에도 여정의 제목이 한국어다** (`어머니 병환 회복`). 이것은 본보기 여정에 적혀 있는 글이고 사용자가 직접 적는 자리이므로 번역 대상이 아니다. 영어 사진을 위해서는 본보기 여정의 제목을 영어로 두는 손잡이가 필요하며, 지금은 없다.

4. **실기기 사진이 아니다.** 이 컨테이너에는 맥도 폰도 없어 웹 빌드를 폰 크기로 띄워 찍었다. 그래서 상태 표시줄(시각·배터리)과 기기 테두리가 없다. 두 스토어 모두 이런 사진을 받지만, 실기기 사진으로 바꿀지는 사람이 정한다.

## 이 폴더는 얼리지 않는다

저장소의 다른 화면 사진 폴더들은 마일스톤이 끝나면 **얼려서** 그때의 기록으로 남긴다. 이 폴더는 다르다 — 스토어에 올릴 사진은 **언제나 지금의 앱**을 보여 줘야 하므로, 화면이 바뀌면 다시 찍어 덮어쓴다.
