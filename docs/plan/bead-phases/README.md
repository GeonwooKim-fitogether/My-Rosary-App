# 지금 알의 다섯 상태 — 화면 사진 다섯 장 (FR-15)

> 한 줄 요지: **기도 화면 가운데의 지금 알이 이제 "어디까지 왔나"뿐 아니라 "지금 무슨 일이 벌어지고 있나"를 말한다.** 앱이 읽는 중인지, 내가 받을 차례인지, 소리 없이 진행 중인지, 단이 막 바뀌었는지, 멈춰 있는지가 다섯 가지 다른 모양이다. 이 폴더의 다섯 장은 그 다섯이 **움직임 없이도** 서로 갈리는지를 눈으로 판정하기 위한 것이다.

## 무엇이 바뀌었나

2026-09-11 까지 묵주 그림은 진행만 말했다. 이미 바친 알이 환해지고 지금 알이 크게 부풀어 숨을 쉬었지만, 그 숨은 앱이 읽는 중이든 내 차례든 멈춰 있든 언제나 같은 속도로 돌았다. 요구사항 FR-15 와 화면 명세(`docs/product/06-screen-spec.md` 화면 B 요소 표)가 다섯 상태와 그 표현을 이미 정해 두었는데, 구현은 그 값을 받을 통로가 없었다 — 진행기(`src/prayer/runner.ts`)는 "지금 읽는 중이다"를 아무에게도 알리지 않았고, 화면(`app/pray.tsx`)은 묵주 그림에 자리 정보만 넘겼다.

2026-09-12 에 그 통로를 만들었다. 진행기가 읽기 시작할 때 · 사이가 시작될 때 · 단이 바뀔 때 상태를 알리고(`onPhase`), 세션 갈고리(`src/prayer/usePrayerSession.ts`)가 거기에 멈춤을 얹어 값 하나(`phase`)로 내보내며, 묵주 그림(`src/prayer/Rosary.tsx`)이 그 값으로 지금 알을 그린다. 상태의 이름과 뜻은 `src/prayer/phase.ts` 한 곳에 있다.

| 상태 | 움직임이 있는 기기에서 | 동작 줄이기를 켠 기기에서 (이 폴더의 사진) |
|---|---|---|
| 읽는 중 | 알 바깥의 테두리가 시계 방향으로 차오른다. 읽는 절의 어림 길이에 맞춘다 | 테두리가 다 차 있다 |
| 내 차례 | 4초 주기로 부풀며 밝아졌다 어두워진다 | 지금까지의 모습 그대로 — 치자색 알과 옅은 빛무리 |
| 소리 없이 진행 | 알을 넘기는 진동에 맞춰 빛무리가 한 번 반짝이고 가라앉는다 | 빛무리가 평소보다 짙다 |
| 단 전환 | 한 번 크게 부풀었다 돌아온다 | 부푼 채 서 있다 |
| 멈춤 | 호흡이 멎고 빛무리가 꺼지며 알이 흐려진다 | 같다 — 움직임이 없는 상태다 |

## 값은 어디서 왔나

시안(`docs/design/v5/index.html`)에는 움직임이 하나뿐이다 — `@keyframes bre`, 4초 주기로 크기 1 에서 1.12 로 부풀고 투명도 .42 에서 1 로 밝아지는 숨. 다섯 상태 중 "내 차례"는 그것을 그대로 쓰고, 나머지 넷은 **그 숨과 디자인 시스템 §6 의 모션 표에서 파생했다.** 새로 지어낸 값은 없다.

| 값 | 어디서 왔나 |
|---|---|
| 단 전환의 맥동 폭 1.12 | 시안 `bre` 의 크기 폭 |
| 단 전환의 맥동 시간 500ms | 디자인 시스템 §6 화면 전환 500ms — "한 상태에서 다른 상태로 넘어가는 움직임"에 해당하는 가장 가까운 값 |
| 반짝임이 가라앉는 시간 450ms | 디자인 시스템 §6 글자 교체 450ms — 알이 넘어갈 때 함께 일어나는 움직임 |
| 반짝임의 밝은 끝 1 과 가라앉은 끝 .14 | 시안 `bre` 의 밝은 끝과 시안 후광의 `opacity=".14"` |
| 멈춤의 흐려짐 .42 | 시안 `bre` 의 어두운 끝 — 숨이 가장 어두운 자리에서 멎은 것 |
| 동작 줄이기에서 소리 없이 진행의 빛무리 .42 | 반짝임이 지나는 길(1 에서 .14) 위의 값. 내 차례(.14)와 움직임 없이 갈리게 세웠다 |
| 읽는 중 테두리의 굵기 1.8 · 알에서 3.6 떨어짐 | 시안에 없는 그림이라 줄의 바깥 결 굵기(`THREAD.outer` 1.8)를 빌렸다. 알이 숨 쉴 때 닿는 크기(19)보다 바깥(20.6)이라 두 상태가 겹치지 않는다 |
| 읽는 중 테두리가 차오르는 시간 | 소리 통로가 안전망에 쓰는 어림식 `380ms + 글자수 × 66ms`(최대 4200ms) — 기기는 낭송이 얼마나 걸릴지 미리 말해 주지 않는다 |

## 사진 다섯 장 — 무엇을 보며 확인하나

모두 붉은 장미(기본값) · 낮 벌 · 390×844 이고, 동작 줄이기를 켠 상태로 찍었다. 그래서 여기 보이는 것은 **정지된 모양의 차이**다 — 움직임을 볼 수 없는 사용자가 실제로 보는 모습이며, 다섯 장을 나란히 놓고 "어느 것이 어느 상태인지 알아볼 수 있는가"를 묻는다.

| 파일 | 상태 | 무엇을 보나 |
|---|---|---|
| `1-reading.png` | 읽는 중 | 지금 알(제1단 둘째 성모송) 바깥에 치자색 **테두리**가 한 바퀴 서 있다. 이 테두리는 다른 넷에 없다 |
| `2-response.png` | 내 차례 | 테두리 없이 치자색 알과 옅은 빛무리 — 2026-09-11 까지 늘 보이던 모습이다 |
| `3-paused.png` | 멈춤 | 빛무리가 없고 알이 **흐리다**. 이어폰의 일시정지 단추로 화면 안에서 멈춘 상태다 |
| `4-decade.png` | 단 전환 | 제2단의 신비 선포 — 지금 자리가 큰 알이고, 그 알이 평소보다 **부풀어** 있다 |
| `5-silent.png` | 소리 없이 진행 | 읽지 않기로 만든 여정. 빛무리가 내 차례보다 **짙어** 알 둘레가 더 환하다 |

## 정직하게 적어 두는 한계

- **멈춤에서 알 위의 숫자가 읽기 어려워진다** (`3-paused.png` 의 `2`). 알이 .42 로 흐려지는데 숫자는 그대로 두었으므로, 한지 바탕과 섞인 흐린 치자 위에 밝은 숫자가 놓여 대비가 떨어진다. 숫자까지 함께 흐리면 아예 사라지므로 그대로 두었다. 멈춤은 사용자가 앱을 벗어났다 돌아온 상태라 그 순간 숫자를 읽어야 할 일은 드물지만, 흐려짐의 값(.42)을 올리거나 멈춤을 흐려짐 대신 다른 모양으로 말하는 것은 판단이 갈리는 자리다. 결정 큐에 올렸다.
- **읽는 중 테두리는 어림이다.** 기기가 실제로 얼마나 오래 읽을지는 알 수 없어 시안이 쓰던 어림식으로 차오른다. 실제 낭송이 어림보다 빠르면 테두리가 다 차기 전에 다음 상태로 넘어가 걷히고, 느리면 다 찬 채로 기다린다. 어느 쪽도 거짓을 말하지는 않지만 "정확히 끝나는 순간에 다 찬다"는 아니다.
- **움직임이 있는 기기의 모습은 사진에 없다.** 애니메이션은 브라우저에서 한 번 돌려 테두리가 부분적으로 차오르고 반지름이 시간에 따라 바뀌는 것을 값으로 확인했지만(`e2e` 밖의 일회성 확인), 저장소의 사진은 모두 동작 줄이기 상태다. 실기기에서의 느낌은 사람이 봐야 한다.
- **전부 읽기 방식의 사이는 "내 차례"로 그린다.** 전부 읽기는 앱이 앞 절과 뒷 절을 다 읽으므로 사용자 몫이 없는데, 그 뒤의 짧은 쉼(900ms)을 무슨 상태로 볼지 명세가 정하지 않았다. 알이 쉬는 자리로 보아 숨을 쉬게 두었다.

## 사진을 다시 찍는 법

```bash
npx expo export --platform web
npx playwright test e2e/bead-phases.spec.ts
```

이 시험은 사진만 찍지 않는다. 상태마다 화면이 묵주 상자에 붙이는 낭독기용 이름(`지금 알: 앱이 읽는 중` 등)을 읽어 값으로 확인하므로, 그림이 어긋나도 이름이 어긋나면 시험이 먼저 알려 준다.
