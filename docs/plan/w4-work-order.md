## 1. 이 마일스톤이 앞의 넷과 다른 점 — 경계를 먼저 긋는다

W0~W3 은 전부 이 컨테이너 안에서 끝낼 수 있었다. **W4 는 그렇지 않다.** 결정 12-1 이 위임하지 않은 자리 넷 중 **둘(돈이 나가는 것 · 바깥으로 나가는 것)이 이 마일스톤의 한복판에 있다.**

| 이 지시서가 다루는 것 (계정 없이 된다) | 이 지시서가 다루지 않는 것 (사람만) |
|---|---|
| ① 설치형 웹앱 — 매니페스트 · 서비스 워커 · 오프라인 캐시 | 스토어 계정 셋 (Apple 연 $99 · Google $25 · Expo) — **돈** |
| ③ 언어를 한국어 · 영어 둘만 켜고 나머지 다섯은 스위치 뒤로 | 공개 주소에 올리기 — **바깥 노출** |
| ④ 소개 시트(S7)를 시안 어법으로 | EAS 스토어 빌드 (계정이 있어야 돈다) |
| ⑤ 기기에서도 기록을 지킨다 (Q-73) | 검증 참가자 모집 · 실기기 확인 · 기도문 판본 대조 |

### 1-1. 순서에 함정이 하나 있다 — Q-73 의 전제가 깨질 수 있다

Q-73 은 기기용 기록 내보내기·들여오기를 W4 로 미루면서 이렇게 적었다: **"W4 가 기기 빌드를 처음 돌리는 자리이므로 거기서 검증할 수 있다."**

그런데 **기기 빌드는 스토어 계정이 있어야 돈다.** 계정이 아직 없으면 W4 에서도 그 코드는 검증되지 않고, Q-73 이 피하려 했던 "넣었는데 되는지 모르는 상태"가 그대로 이어진다.

**그래도 넣는다.** 까닭은 둘이다. 첫째, 계정은 사람이 만드는 것이고 그 일은 이미 부탁으로 나가 있다 — 코드가 먼저 준비돼 있어야 계정이 생기는 즉시 빌드로 확인할 수 있다. 둘째, **넣지 않으면 앱 스토어 사용자가 기록을 잃는 위험이 그대로 남는데**, 그 위험은 계정 유무와 무관하게 실재한다.

**다만 검증되지 않았다는 사실을 침묵하지 않는다.** 이 슬라이스의 보고와 파일 머리글에 **"기기에서 아직 한 번도 돌려 보지 못했다 — 웹에서만 확인했다"** 를 분명히 적는다.

## 2. 만들 것 — 얇은 완결 단위 넷

### 슬라이스 A — 설치형 웹앱

Expo 의 웹 내보내기(`npm run build:web` 이 만드는 `dist/`)에 아래 넷을 붙인다.

1. **매니페스트**(`manifest.webmanifest`) — 앱 이름 · 아이콘 · 시작 주소 · 표시 방식(`standalone`) · 바탕색. 시안이 이미 하나를 갖고 있으니(`docs/design/world/manifest.webmanifest`) **값의 본보기로 읽되 그대로 베끼지 말고** 이 앱의 실제 이름·아이콘으로 채운다.
2. **서비스 워커** — 앱 껍데기와 글꼴·성화를 캐시해 **비행기 모드에서도 열리게** 한다. Expo 는 이것을 기본으로 주지 않으므로 작은 것을 직접 쓴다. 시안의 `sw.js` 가 본보기다.
3. **"홈 화면에 추가" 안내** — 설정 화면에 그 줄이 이미 자리만 잡혀 있다(`app/settings.tsx` 머리글이 "지금 놓으면 눌러도 아무 일이 없다"고 적어 둔 자리). 이제 뜻이 생겼으니 **그 줄을 살린다.** iOS 사파리는 프로그램으로 설치를 띄울 수 없으므로 **안내 문구**여야 하고, 안드로이드 크롬은 설치 프롬프트를 띄울 수 있다 — 둘을 갈라 처리한다.
4. **오프라인에서 무엇이 되고 무엇이 안 되는지**를 그 안내에 한 줄로 적는다.

**검증:** 크로미움에서 비행기 모드(네트워크 차단)로 열어 기도 화면까지 가는 e2e 하나. 캐시가 실제로 도는지를 재는 것이 요점이다.

### 슬라이스 B — 언어를 둘로 좁힌다 (결정 12-C)

지금 일곱 언어가 모두 고를 수 있다. 결정 12 가 **"한국어와 영어 둘만 켜고 나머지 다섯은 스위치 뒤"** 로 정했다. 까닭은 로드맵 §7 이 적은 위험이다 — **틀린 기도문을 바치게 하는 사고**를 막기 위해, 사람이 확인한 언어만 켠다.

- 켜진 언어만 지역·언어 화면에서 고를 수 있게 한다.
- 데이터에 **`verified: false`** 를 명시한다(로드맵 §7 의 대비가 그렇게 적었다). 확인되지 않은 기도문이 무엇인지 코드에서 보이게 하는 것이 목적이다.
- **다섯을 지우지 않는다.** 스위치 하나로 다시 켤 수 있어야 한다.

### 슬라이스 C — 소개 시트 (S7)

08 검증에 들어온 사람이 처음 앱을 열었을 때 무엇을 하는 앱인지 한 장으로 말한다. 시안에 없는 화면이므로 **시안의 시트 어법에서 파생한다** — W1~W3 이 시트 일곱에 대해 이미 한 일과 같다(`src/ui/Sheet.tsx`).

### 슬라이스 D — 기기에서도 기록을 지킨다 (Q-73)

부품 둘(`expo-sharing` · `expo-document-picker`)을 들이고 **통로 한 파일**(`src/storage/backupFile.ts`)만 갈아 끼운다. 규칙 파일(`src/storage/backup.ts`, 무엇을 담고 무엇을 거절하나)은 **한 줄도 건드리지 않는다** — 슬라이스 C 가 규칙과 통로를 가른 덕분에 이 일이 싸다.

**§1-1 을 반드시 지킨다** — 기기에서 확인하지 못했다는 사실을 보고와 파일 머리글에 적는다.

## 3. 통과 조건

1. 타입 검사와 단위 시험 통과 (**기준선 497개**).
2. e2e 전체 통과 (**기준선 59개**) + 오프라인 e2e 하나 추가.
3. 언어를 영어로 바꿔도 화면이 무너지지 않는 것을 사진으로 확인 — **지금까지 한국어 화면만 찍어 왔다.**
4. 화면 사진을 `docs/plan/w4-screens/` 에 두고 `README.md` 로 설명한다.
5. **사람 몫으로 남은 것을 보고에 부탁 서식(communication 규칙 8-2)으로 적는다.** 무엇이 막혀 있고 무엇이 그것을 푸는지가 보여야 한다.
