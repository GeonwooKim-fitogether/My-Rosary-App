# W1 화면 사진 — 새 시안의 어법으로 다시 세운 기도 화면

> 한 줄 요지: **여덟 장은 「MyRosary World」 시안(`docs/design/world/`)의 어법으로 다시 세운 기도 화면을 이 컨테이너의 브라우저에서 실제로 찍은 것이고, 네 장은 너비 넷에서, 두 장은 지금 자리가 알이 아닐 때와 알일 때를, 두 장은 둘째 슬라이스가 더한 것(앱 안 글자 크기와 나가는 시트)을 보여 준다.**

찍는 일은 사람이 손으로 하지 않는다. `e2e/screenshots.spec.ts` 의 `W1 · …` 세 시험과 `e2e/font-scale.spec.ts` 의 셋째 시험이 앱을 실제로 띄워 같은 단계까지 옮긴 뒤 찍으므로, 사진은 언제 다시 찍어도 같은 자리에서 나온다.

## 무엇을 보는 사진인가

| 파일 | 크기 | 무엇을 보는가 |
|---|---|---|
| `pray-320.png` | 320×844 | 가장 좁은 기기. 묵주 칸의 높이를 **가로**가 정하는 쪽이다 — `66vw × 1.35 = 285` 이 `38dvh = 321` 보다 작다 |
| `pray-375.png` | 375×844 | 같은 갈래. `66vw × 1.35 = 334` |
| `pray-390.png` | 390×844 | 시안이 그려진 크기. 여기서부터 **세로**가 높이를 정한다 — `38dvh = 321` 이 `66vw × 1.35 = 348` 보다 작다 |
| `pray-430.png` | 430×844 | 가장 넓은 기기. 여전히 세로가 정한다 |
| `pray-cross.png` | 390×844 | 하루의 첫 단계(성호경). 지금 자리가 **알이 아닌 곳**(십자가)일 때 빛무리와 테가 어떻게 서는지 |
| `pray-bead.png` | 390×844 | 제3단의 넷째 성모송. 지금 자리가 **고리 위의 알**일 때 |
| `pray-xlarge.png` | 390×844 | 앱 안 글자 크기를 가장 큰 자리(`아주 크게` · 27px)로 올린 사도신경. 가장 큰 글자와 가장 긴 기도문이 만나는 자리에서 글이 잘리지 않는지를 본다 (W1 통과 조건 5 의 뒷부분) |
| `pray-leave.png` | 390×844 | 머리의 뒤로 화살표를 눌렀을 때 열리는 **나가는 방법을 묻는 시트**. `잠시 멈춤`(자리가 남습니다)과 `여기서 끝내기`(오늘 처음부터)가 글자로 선다 |

너비 넷을 고른 이유는 이 화면의 크기가 화면 크기에서 계산되기 때문이다. 묵주 칸의 높이가 `min(38dvh, 66vw × 1.35, 400px)` 이라, 좁은 기기에서는 가로가 높이를 정하고 넓은 기기에서는 세로가 정한다. 두 갈래를 다 찍어야 "묵주와 기도문이 겹치지 않는가"(W1 통과 조건 4)가 판정된다. 겹치지 않는다는 것은 눈으로만 보지 않고 사진을 찍는 시험이 값으로도 확인한다 — 기도문의 첫 글자가 언제나 묵주 칸의 아래 끝보다 아래에 있어야 통과다.

## 사진에서 확인하는 것 다섯

1. **고리가 원이다.** 옛 화면의 물방울(하트) 모양은 사라졌다. 알 쉰넷이 원둘레를 쉰여섯 칸으로 나눈 자리에 고르게 앉고, 맨 아래 두 칸이 비어 그 틈으로 꼬리가 내려간다 (`decisions.md` 결정 12-2 의 카드 D).
2. **지금 알이 부풀지 않는다.** 옛 화면은 지금 알만 반지름 17 로 키워 눈을 끌었다. 지금은 알을 제자리에 두고 **빛무리와 테**로만 말한다. `pray-bead.png` 에서 고리 위쪽의 흰 알 하나가 그것이고, `pray-cross.png` 에서는 십자가가 같은 방식으로 빛난다.
3. **어디까지 바쳤는지가 빛으로 보인다** (결정 10). 꼬리에서 출발해 고리를 오른쪽으로 돌아 지금 알까지가 환하고, 그 너머는 차분하다. 알이 채워지는 것이 아니라 **밝아지는 것**이 진행이다 — 실제 묵주는 기도한다고 알이 채워지지 않기 때문이다.
4. **성화가 띠가 아니라 배경이다.** 화면 전체를 덮고 위에서 아래로 지역의 덮개 색에 가라앉는다. 글자는 그 위에 얹힌다.
5. **기도문의 아래 끝이 부드럽게 사라진다.** 넘치는 글은 잘리지 않고 그 칸 안에서 스크롤된다. 시안은 `mask-image` 로 마지막 22px 을 지우는데 React Native 에 그 속성이 없어, 같은 높이만큼 덮개 색 그러데이션을 얹어 같은 인상을 만들었다.

## 둘째 슬라이스에서 이 사진들이 어떻게 달라졌나 (2026-09-18)

첫 슬라이스(§3-1~§3-4) 뒤에 찍은 여섯 장도 함께 다시 찍혔다. 화면이 바뀌었기 때문이며, 무엇이 달라졌는지 적어 둔다.

1. **기도문이 시안의 크기가 됐다.** 이 저장소의 옛 서체 계단(앞 절 26px · 뒷 절 21px · 줄 높이 1.7)에서 시안의 값(기본 20px · 줄 높이 1.62)으로 옮겼고, 앞 절과 뒷 절의 크기가 **같아졌다** — 시안의 기도문은 크기 하나짜리 한 덩어리이고 이 앱이 더한 교대는 색과 흐림으로만 갈린다.
2. **머리 오른쪽에 `Aa` 단추가 섰다.** 누를 때마다 넷(17 · 20 · 23 · 27)을 한 칸씩 돌고 넷째에서 처음으로 돌아온다. 그 자리에 있던 잠시 멈춤 아이콘 단추는 사라졌다(아래 3번).
3. **머리 왼쪽의 뒤로 화살표가 이제 묻기만 한다.** 그전에는 한 번 누르면 오늘 바친 자리가 곧바로 지워졌다. 지금은 `pray-leave.png` 의 시트가 열리고 사람이 나가는 길을 고른다.
4. **머리가 위로 올라붙었다.** 위 여백이 고정값 44 에서 시안과 같은 **안전 영역 + 6** 으로 바뀌었고, 브라우저에는 안전 영역이 없어 6 이 된다. 노치가 있는 기기에서는 그만큼 내려온다.

## 이 사진이 아직 보여 주지 못하는 것

정직하게 적어 둔다.

- **하루 완주 화면은 이 폴더에 없다.** 새 어법으로 옮겼고(§3-6), 그 사진은 `docs/plan/m1-screens/day-done.png` 가 계속 찍는다.
- **고리를 손가락으로 돌리는 감각은 사진에 담기지 않는다.** 그 조작이 실제로 동작하는지는 `e2e/ring-drag.spec.ts` 가 재고, **손가락에 어떻게 느껴지는지는 실기기에서 사람이 봐야 한다.** 고리를 잡았다고 볼 거리(반지름의 0.6~1.45배)와 끌기 문턱(3도)은 그 회신 뒤 조정을 전제로 둔 값이며, `src/prayer/rosaryState.ts` 의 `RING_GRAB` 과 `DRAG_THRESHOLD_DEG` 한 자리에 모여 있다.
- **소리·진동·이어폰 단추는 이 컨테이너에 없다.** 알을 옮길 때의 12ms 짜리 짧은 진동도 사진으로는 확인할 수 없다.

## 옛 사진들과의 관계

`docs/plan/` 아래의 다른 기도 화면 사진들은 두 갈래로 갈린다.

**얼린 계보** — `m1-screens/pray.png` · `m2-screens/pray-night.png` · `rosary-full/` · `prayer-order/` · `rosary-materials/` · `rosary-lit/` 은 옛 어법(물방울 고리)의 화면을 담고 있고, 그것을 찍던 시험 여섯은 은퇴했다(`e2e/screenshots.spec.ts` 의 주석). 결정 6·7·8·9·10 이 가리키는 증거이므로 덮지 않는다.

**살아 있는 사진** — `bead-phases/` 와 `font-scale/` 은 지금도 시험이 다시 찍으므로 새 화면을 담는다. 두 폴더의 README 는 각자 자기 폴더가 무엇을 재는지 적고 있고, `font-scale/README.md` 는 2026-09-18 에 새 크기에 맞춰 고쳤다. `bead-phases/README.md` 에는 아직 옛 화면을 설명하는 대목(알 위의 숫자)이 남아 있다.
