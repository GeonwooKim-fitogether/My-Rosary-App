# W0 작업 지시서 — 새 시안의 바닥을 앉힌다

> 한 줄 요지: **W0 에서 만드는 것은 화면이 아니라 화면이 서기 위한 바닥 다섯이다** — 「Classical」 디자인 토큰과 지역 다섯의 색 벌, 글꼴 셋, 언어 일곱의 데이터, 성화 열일곱 장과 초점 표, 그리고 그것들을 고르는 설정. 화면은 한 장도 만들지 않는다. 기도 화면은 W1 의 일이다.

받는 사람 KimDeveloper · 쓴 사람 지휘 세션 · 2026-09-17 · 브랜치 `claude/my-rosary-app-development-pmbcy9` · PR #3

**먼저 읽을 것 셋.** `decisions.md`(결정 11 과 결정 큐 Q-44~Q-50) · [`docs/plan/roadmap-world.md`](./roadmap-world.md)(W0~W5 전체와 §3 의 결정 카드) · [`docs/design/world/README.md`](../design/world/README.md)(시안 정본의 구조와 여는 법). 이 지시서는 그 셋을 대신하지 않고, W0 에서 무엇을 어떤 순서로 만들고 무엇으로 통과 판정을 받는지만 정한다.

## 1. 착수 전에 직접 재서 확인한 사실 넷

이 넷이 W0 의 범위를 그대로 정했으므로 가장 먼저 적는다.

| 확인한 것 | 결과 | 이것이 W0 에 뜻하는 바 |
|---|---|---|
| Google Fonts 주소 | **이 컨테이너에서 막혀 있다** | 시안처럼 웹에서 받아 쓸 수 없다. 대신 npm 의 `@expo-google-fonts/*` 가 같은 글꼴의 TTF 파일을 담아 온다 — 세 꾸러미 모두 조회됐다(cormorant-garamond 0.4.1 · lora 0.4.2 · noto-serif-kr 0.4.3). 앱은 어차피 인터넷 없이도 글꼴이 있어야 하므로 번들이 옳은 길이다 |
| 한국어 명조가 이미 번들에 있는가 | **있다** — `assets/fonts/NotoSerifKR-Regular.ttf` | 새로 받을 것은 라틴 글꼴 둘(Cormorant Garamond · Lora)뿐이다. 한글 글꼴은 파일이 크므로 이미 있는 것을 쓴다 |
| 시안의 기도문이 앞 절과 뒷 절로 나뉘어 있는가 | **나뉘어 있지 않다** — 한 문자열이다 | 이 저장소의 `spec/prayers.ko.json` 은 `a`(앱이 읽는 앞 절)와 `b`(사용자가 받는 뒷 절)로 나뉜다. 교대 낭송(FR-11)이 그 나눔 위에 서 있다. **그래서 시안의 기도문은 그대로 쓸 수 없다** — §3-3 이 이것을 어떻게 다루는지 정한다 |
| 시안이 오늘의 신비를 정하는 규칙 | **요일 규칙 하나뿐** | 54일 기도의 순환(환희 → 고통 → 영광, FR-43)을 모른다. 규칙은 `spec/mysteries.json` 이 이긴다(로드맵 §2 원칙 2). W0 는 데이터만 옮기고 규칙은 건드리지 않는다 |

## 2. W0 의 목적 — 화면을 한 장도 만들지 않는 이유

W0 가 답하려는 질문은 하나다. **"새 시안이 쓰는 재료 — 색 다섯 벌, 글꼴 셋, 언어 일곱, 성화 열일곱 — 이 이 저장소의 코드로 실제로 서는가?"**

화면을 함께 만들면 재료가 틀렸다는 것을 화면을 다 만든 뒤에 알게 된다. 재료만 먼저 세우면 W1 의 기도 화면은 그 재료를 골라 쓰기만 하면 된다. M0 가 화면 한 장으로 바닥을 관통해 본 것과 같은 이유이고, 이번에는 바닥이 이미 서 있으므로 화면조차 필요 없다 — 시험과 빌드가 증명한다.

**살아남는 것을 다시 못 박는다.** `spec/` 의 기도 규칙, `src/prayer/` 의 진행기와 소리·진동, `src/journey/` 의 여정 규칙, `src/storage/` 의 저장은 W0 에서 **하나도 고치지 않는다.** 새 시안은 겉을 바꾸지 속을 바꾸지 않는다.

## 3. 만들 것 다섯

### 3-1. 「Classical」 토큰과 지역 다섯의 색 벌

`src/theme/tokens.ts` 에 **새 벌로 더한다. 한지 벌(`dayColors`·`nightColors`)은 지우지 않는다** — 계보이고, W1 이 끝날 때까지 기존 화면이 그 값으로 서 있어야 한다.

값의 출처는 둘이다.

| 무엇 | 어디서 읽나 |
|---|---|
| 토큰 체계 (간격 · 반지름 · 그림자 · 글꼴 역할) | `docs/design/world/_ds/classical-*/styles.css` 의 `:root` 선언 |
| 지역 다섯의 색 (paper · ink · accent · accent2 · scrim · muted) | `docs/design/world/data.js` 의 `REGIONS` 배열 |

지역 다섯은 유럽 · 북미 · 남미 · 아시아 · 한국이고, 색이 여섯 개씩이다. **다섯 벌 전부에 대해 대비를 계산해 시험으로 지킨다** — 기존 `src/theme/tokens.test.ts` 가 낮·밤 두 벌에 하던 그대로다. 기준은 결정 큐 Q-43 이 정한 대로 글자 4.5:1, 그림 요소 3:1 이다. **미달하는 색이 나오면 값을 조용히 고치지 말고 시험이 실패하게 둔 뒤 보고에 적는다** — 시안의 값을 고치는 것은 판단이 갈리는 자리다.

### 3-2. 글꼴 셋

`npm i @expo-google-fonts/cormorant-garamond @expo-google-fonts/lora` 로 받아 TTF 파일을 `assets/fonts/` 로 옮긴다. 필요한 굵기만 가져온다 — Cormorant Garamond 는 500·600, Lora 는 400·600 이다(시안의 `styles.css` 가 그 넷만 부른다). 한글은 이미 있는 `NotoSerifKR-Regular.ttf` 를 쓴다.

`src/theme/tokens.ts` 의 `fonts` 표에 이름을 더하고, 글꼴을 싣는 자리(`app/_layout.tsx` 의 `useFonts`)에 세 줄을 더한다. **꾸러미 자체는 의존성으로 남기지 않는다** — 파일만 꺼내 쓰고 `package.json` 에서 뺀다. 번들에 들어가는 것은 TTF 파일이지 꾸러미가 아니기 때문이다.

### 3-3. 언어 일곱의 데이터 — 기도문은 조심해서 다룬다

`docs/design/world/data.js` 를 분해해 이 저장소의 자리에 앉힌다. 그 파일은 ES 모듈이라 `node` 로 불러 JSON 으로 쏟아 낼 수 있다. **손으로 옮겨 적지 않는다** — 일곱 언어 × 여덟 기도문을 손으로 옮기면 반드시 한 글자가 틀린다.

| 무엇 | 어디에 | 어떻게 |
|---|---|---|
| 화면 문구 일곱 벌 (`UI`) | `src/i18n/` | 언어마다 파일 하나. 키가 일곱 벌 모두에서 같은지 시험이 지킨다 |
| 신비 이름 · 성경 구절 · 묵상 노트 | `spec/mysteries.world.json` | 기존 `spec/mysteries.json`(규칙)은 건드리지 않는다. 이름과 해설만 새 파일로 |
| 기도문 일곱 벌 | `spec/prayers/<언어>.world.json` | **앞 절과 뒷 절로 나뉘어 있지 않은 채로** 들어온다 |

기도문의 세 가지를 반드시 지킨다.

1. **한국어는 이 저장소의 `spec/prayers.ko.json` 이 정본이다.** 시안의 한국어 기도문으로 덮어쓰지 않는다. 시안 것은 `prayers/ko.world.json` 으로 나란히 두어 나중에 대조할 수 있게만 한다.
2. **모든 새 파일에 `verified: false` 와 출처를 적는다.** 시안의 기도문은 Claude Design 이 쓴 것이고 공식 기도서와 대조되지 않았다. 이 저장소는 기도문을 기억에 기대어 넣지 않는다(결정 큐 Q-39 · D-4).
3. **나뉘지 않은 기도문은 낭송에 연결하지 않는다.** 교대 낭송은 `a`·`b` 나눔 위에 서 있는데 새 언어에는 그 나눔이 없다. 나눔은 그 언어의 전례 관습을 아는 사람이 해야 하므로, W0 는 **데이터를 들여오고 "아직 나뉘지 않았다"를 파일에 적는 데까지만** 한다. 이것이 로드맵 §3 카드 C(언어 범위)가 묻는 바로 그 자리다.

### 3-4. 성화 열일곱 장과 초점 표

그림을 `assets/art/world/` 로 옮기고, 표를 `src/art/worldPlates.ts` 에 만든다. 값의 출처는 `data.js` 의 `IMAGES`(초점 좌표와 한·영 제목)와 `REGIONS[].images`(지역마다 쓰는 그림 목록)다.

기존 `src/art/plates.ts`(v5 의 열여섯 장, 네 슬롯별 초점)는 **지우지 않는다.** 두 표가 다른 그림과 다른 슬롯 체계를 갖고 있고, W1 이 새 표로 옮겨 갈 때까지 기존 화면이 옛 표로 서 있어야 한다.

**워터마크 한 장을 표에 표시한다.** `12-mary-child-neutral.jpg` 오른쪽 아래에 작가 서명이 있다(결정 큐 Q-50). 지금 빼지는 않되, 표에 `watermark: true` 를 달아 정식 자산 교체(D-1) 때 찾을 수 있게 한다.

### 3-5. 설정에 지역과 언어를 넣는다

`src/storage/settings.ts` 의 `AppSettings` 에 `region` 과 `language` 를 더한다. 기본값은 한국·한국어다. 기존 설정이 저장된 기기에서 두 값이 없으면 기본값으로 채워지는지 `parseSettings` 시험으로 지킨다 — 이 파일은 이미 그 방식으로 모든 항목을 지키고 있다.

문구를 고르는 함수 하나(`src/i18n/` 의 조회)를 함께 만든다. **켜진 언어만 고를 수 있게 한다** — 로드맵 카드 C 의 추천대로 한국어와 영어만 켜고, 나머지 다섯은 데이터는 들어오되 목록에 뜨지 않는다. 켜고 끄는 것이 스위치 한 줄이어야 한다.

## 4. 무엇이 통과인가 — W0 작업완료의 조건 다섯

1. **타입 검사 통과** (`npm run typecheck`).
2. **단위 시험 통과** — 기존 294 개가 그대로 통과하고, 새로 넷이 붙는다. 지역 다섯 벌의 대비, 언어 일곱의 문구 키가 빠짐없이 같은지, 성화 표의 파일이 실제로 있는지, 설정이 옛 저장본을 읽어도 깨지지 않는지.
3. **웹 빌드 성공** (`npm run build:web`) — 글꼴 셋이 실제로 번들에 들어가는 것을 여기서 확인한다.
4. **기존 e2e 서른이 그대로 통과** — W0 는 화면을 건드리지 않으므로 하나도 깨지면 안 된다. 깨진다면 속을 건드린 것이다.
5. **실제 글꼴이 얹힌 화면 한 장** — `docs/plan/world-screens/` 의 사진은 대체 글꼴로 찍힌 것이다(Q-49). 번들한 글꼴로 한 장을 찍어 그 폴더에 더하고, 무엇이 달라졌는지 README 에 한 줄 적는다.

## 5. 지킬 것과 하지 말 것

- **값을 새로 정하지 않는다.** 색·간격·초점은 시안에서 읽어 옮기는 것이고, 옮기는 사람이 고르는 자리가 아니다. 시안에 없어서 정해야 하는 것이 나오면 결정 큐에 한 줄 남기고 진행한다.
- **기존 화면과 엔진을 건드리지 않는다.** W0 에서 `app/` 아래 파일을 고치는 것은 글꼴을 싣는 `_layout.tsx` 한 곳뿐이다.
- **`.claude/` 아래를 고치지 않는다.** 공용 자산의 원본은 창고다.
- **`git add -A` 를 쓰지 않는다.** 만진 파일만 이름으로 더한다 — 화면 사진은 e2e 가 돌 때마다 바뀌어 섞여 들어간다.
- **`decisions.md` 는 지휘 세션이 적는다.** 결정 큐에 넣을 것이 생기면 보고에 적어 넘긴다.

## 6. 못 하는 것 — 보고에 이 이름 그대로 적을 것

- **기도문이 공식 문구인지 확인하는 일.** 사람 몫이고 W4 전까지다(D-4).
- **새 언어의 앞 절·뒷 절 나눔.** 그 언어의 전례 관습을 아는 사람이 해야 한다.
- **실기기에서 글꼴이 어떻게 보이는지.** 이 컨테이너에는 폰이 없다.

## 7. 다음 — W0 이 끝나면

W1(기도 화면)이다. 원형 고리 묵주와 고리 드래그, 성화 몰입 배경, 그리고 그 아래에 기존 엔진을 잇는 일이며, 로드맵 §4 의 W1 행이 조건을 적고 있다. W1 은 로드맵 §3 카드 D(묵주 기하)의 답에 걸려 있으므로, 답이 없으면 추천값(시안 기하 + 재질 넷)으로 간다.
