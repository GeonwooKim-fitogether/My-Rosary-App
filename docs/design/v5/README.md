# 묵주 v5 시안 — Atelier 인계본

> 한 줄 요지: **이 폴더가 시안의 정본이다.** atelier에서 확정한 v5 통합 시제품을 2026-09-08에 이 저장소로 옮겨 왔고, 앞으로 화면의 모양·문구·값을 묻는 질문은 여기서 답한다.

## 무엇이 들어 있나

| 무엇 | 어디 | 설명 |
|---|---|---|
| 앱 원본 | `index.html` (54KB) | 화면 열과 기도 엔진이 한 파일에 있다. 그림은 `art/`를 상대 경로로 참조한다 |
| 성화 | `art/` (16장, 1.7MB) | 슬롯마다 초점 좌표를 가진 교체 가능한 자산 |
| 조립기 | `build.mjs` | `node docs/design/v5/build.mjs` 를 돌리면 그림이 박힌 한 파일(`dist/rosary-v5.html`, 3MB)이 나온다. `dist/`는 git에 넣지 않는다 |

**두 형태를 두는 이유.** `index.html`은 사람이 읽고 고치는 원본이라 그림이 파일로 있어야 변경 이력이 읽힌다. 반대로 아티팩트로 띄우거나 파일 하나로 건넬 때는 그림이 안에 들어 있어야 한다. 앱 코드는 두 형태를 모두 견디게 쓰여 있다 — `artUrl()`이 `window.__ART_INLINE` 표가 있으면 그것을, 없으면 `art/` 경로를 쓴다.

**조립기를 고칠 때 주의할 것.** 그림 표(`__ART_INLINE`)는 앱 스크립트보다 **먼저** 와야 한다. 첫 렌더에서 이미 표를 읽기 때문이다. `</body>` 앞에 붙이면 순서가 뒤집혀 그림이 비어 나온다(옮겨 오면서 실제로 겪은 결함이라 적어 둔다).

## 화면 열

로그인(`s-login`) · 초대 코드 입력(`s-invite`) · 홈 여정 목록(`s-home`) · 새 기도(`s-new`) · 함께 바치기 배정(`s-assign`) · 기도(`s-pray`) · 하루 완주(`s-dayDone`) · 여정 상세(`s-journey`) · 여정 완주(`s-allDone`) · 설정(`s-settings`).

이 열은 `decisions.md` 결정 1로 정해진 화면 목록(여덟에서 열로 늘어난 것)과 일치한다 — 초대 코드 입력과 함께 바치기 배정이 별도 화면이다.

## 성화 슬롯 체계 — 인계에서 가장 값진 부분

그림 열여섯 장 각각이 **네 자리(슬롯)에 대한 초점 좌표를 따로** 갖는다. 로그인의 340px 띠, 홈의 96×124 썸네일, 기도 화면의 148px 배경, 완주 화면의 248px 띠다. 같은 그림이라도 띠의 세로 비율이 달라지면 얼굴이 걸리는 자리가 달라지기 때문이며, 이것이 FR-23(묵주가 성화 인물의 이목구비를 가리지 않는다)을 지키는 방법이다.

값은 열여섯 장을 네 기하에 실제로 넣어 렌더하고 눈으로 확인해 정한 것이다. 슬롯마다 `no` 목록이 있어, 어느 초점을 줘도 이목구비가 들어오지 않는 그림은 그 자리에서 뽑지 않는다(예: `06_Side_Jesus`는 기도 배경에서 제외).

**한 세션 안에서는 그림이 고정된다.** 화면을 오갈 때마다 성화가 바뀌면 여정의 정체성이 깨지기 때문이다.

**저작권은 아직 미확정이다**(PRD D-1). 이 열여섯 장은 검증 단계용이며, 정식 출시 자산은 별도 결정을 받는다. 교체는 `art/`에 파일을 넣고 `index.html`의 `ART` 배열에 한 행을 더하는 일이다.

## 구현할 때 이 폴더를 어떻게 쓰나

색·글자 크기·간격은 **한 줄도 스타일시트에 없다.** 전부 각 화면의 인라인 스타일에 글자 그대로 박혀 있어, 화면 하나를 구현할 때 그 화면의 마크업만 보면 값이 다 나온다. 스타일시트에 있는 것은 표현 층(기기 틀을 씌울지, 어느 화면을 보일지, 알이 어떻게 숨쉴지)뿐이다.
