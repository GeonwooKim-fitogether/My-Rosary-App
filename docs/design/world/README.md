# MyRosary World 시안 — Claude Design 인계본

> 한 줄 요지: **이 폴더는 2026-09-16 에 Claude Design 에서 내보낸 「MyRosary World」 시안의 원본이다.** 공방장이 2026-09-17 에 "이 시안으로 최종 개발을 하려고 한다"고 지목했고, 그 뜻은 `decisions.md` 결정 11 이 적는다. 화면의 모양·문구·값을 묻는 질문은 이제 여기서 답하며, 앞선 정본이던 `docs/design/v5/` 는 계보로 내려간다. 개발 순서는 `docs/plan/roadmap-world.md` 가 정본이다.

**2026-09-18 에 인계 꾸러미의 나머지 마흔여섯 파일을 마저 들여왔다.** 처음 옮길 때는 시안을 여는 데 필요한 파일만 골라 담고, 꾸러미의 `uploads/` 와 `docs/` 폴더는 "중복이거나 남의 저작물"이라고 판단해 뺐다. 그 판단이 한 자리에서 틀렸다 — `uploads/01_Approved_Sacred_Images/` 에는 성화 열일곱 장이 **처음 내려받았을 때의 파일 이름 그대로** 들어 있었고, 그 이름이 그림의 출처를 말하는 유일한 물증이었다. 그 폴더가 빠진 탓에 "이 성화들이 어디서 왔나"라는 물음이 몇 주 동안 답을 찾지 못했다(`decisions.md` Q-86). 지금은 마흔여섯 파일이 전부 꾸러미의 구조 그대로 들어와 있고, 아래 표가 무엇이 무엇인지 적는다.

## 인계 꾸러미에 무엇이 있었나 — 마흔여섯 파일의 목록

이 절이 있는 이유를 먼저 적는다. **인계본을 받을 때 "무엇이 왔고 무엇이 빠졌나"를 목록으로 남기지 않으면, 빠진 것을 아무도 모른다.** 이 저장소에서 실제로 그 일이 일어났다 — 성화의 출처를 말해 주는 폴더가 빠진 채 몇 주가 지났고, 빠졌다는 사실 자체가 기록되지 않아 아무도 찾아볼 생각을 하지 못했다. 그래서 앞으로 어떤 인계본을 받든 이런 목록을 함께 만든다.

|---|---|---|---|
| 성화 원본 (원래 파일 이름 그대로) | 17 | `uploads/01_Approved_Sacred_Images/` | **그림은 `assets/art/world/` 의 것과 바이트까지 같고, 다른 것은 이름뿐이다.** 그 이름이 출처의 물증이라 지우지 않는다. 짝을 맞춘 표는 그 폴더의 `README.md` |

**되붙인 화면 셋이 무엇을 보여 주나.** 두 장은 여정 카드의 날짜 격자를 보여 주는데, **한 장은 아홉 열이고 다른 한 장은 열여덟 열이다.** 같은 카드가 상태에 따라 열 수가 달라졌다는 뜻이고, 이것이 나중에 W3 에서 "날짜 격자를 아홉 열로 통일한다"로 정리된 바로 그 문제다(`docs/plan/w3-work-order.md`). 나머지 한 장은 홈 화면으로, 성화 한 장과 오늘의 신비, `이어서 기도하기` 단추, 진행 중 여정 한 줄, 그리고 탭 바 넷이 함께 보인다.

**들여온 마흔여섯 중 열여덟은 저장소에 이미 같은 내용이 있다.** 성화 열일곱 장과 지시문 하나다. 그래도 지우지 않고 둔 이유는 두 가지다. 첫째, 성화는 **이름이 증거**여서 이름을 잃으면 물증이 사라진다. 둘째, 인계본은 받은 모양 그대로 보존해야 나중에 "그때 무엇이 왔나"를 다툴 일이 없다. 그 대가로 이 폴더가 3MB 정도 무거워졌다.

## 여는 법

렌더 엔진이 React 와 Babel 을 외부 주소(unpkg)에서 받아 오므로 **인터넷이 열린 브라우저에서, 파일 주소가 아니라 웹 서버로** 열어야 한다(`data.js` 를 모듈로 불러오기 때문에 `file://` 로는 열리지 않는다).

```bash
python3 -m http.server 8765 --directory docs/design/world
# 브라우저에서 http://localhost:8765/MyRosary%20World.dc.html
```

외부 주소가 막힌 환경(이 저장소의 원격 실행 컨테이너가 그렇다)에서는 같은 판의 React 18.3.1 · React DOM 18.3.1 · Babel standalone 7.29.0 을 따로 받아 로컬로 서빙하고, 페이지가 뜨기 전에 `window.__resources` 에 원래 주소와 로컬 주소의 짝을 넣어 주면 된다 — 런타임의 `cdnScriptFor()` 가 그 표를 먼저 본다. `docs/plan/world-screens/` 의 사진이 그 방법으로 찍은 것이다.

## 구현할 때 이 폴더를 어떻게 쓰나

- **값은 마크업 안에 있다.** v5 와 같이 색·크기·간격은 각 화면의 인라인 스타일에 글자 그대로 박혀 있고, 색 다섯 벌은 `data.js` 의 `REGIONS` 가, 글꼴·간격 토큰은 `_ds/.../styles.css` 가 갖는다. 화면 하나를 옮길 때는 그 화면의 `<section data-screen-label="...">` 블록과 `renderVals()` 에서 그 화면에 값을 주는 줄을 함께 본다.
- **기도의 규칙은 여기가 아니라 `spec/` 이 정본이다.** 시안의 `buildSequence()` 는 이 저장소의 81단계와 같은 순서를 만들지만, 오늘의 신비는 요일 규칙 하나만 알고 54일 순환(FR-43)을 모른다. 시안은 화면과 조작을 정하고, 기도가 어떻게 흐르는지는 `spec/` 을 따른다 — v5 를 옮길 때와 같은 원칙이다.
- **묵주 기하는 `renderVals()` 의 "rosary geometry" 절에 있다.** 고리 반지름 96 에 슬롯 56(알 54 + 빈 자리 2), 꼬리 다섯 알의 좌표, 메달과 십자가 경로, 지금 알의 빛무리 값. 알은 움직이지 않고 빛만 옮겨 간다(`rotFor()` 가 0 을 돌려 준다).
- **글꼴은 Google Fonts 에서 받는다**(Cormorant Garamond · Lora · Noto Serif KR). 앱에서는 세 글꼴을 번들해야 한다 — 셋 모두 오픈 폰트 라이선스(OFL)다.

## 시안이 v5 와 다른 점 — 한눈에

| | v5 (2026-09-08 정본) | MyRosary World (이 폴더) |
|---|---|---|
| 대상 | 한국어 · 한국 신자 | 지역 다섯 · 언어 일곱 |
| 계정·조 | 로그인 필수, 초대 코드, 함께 바치기 | 없음 — 기기 저장만 |
| 묵주 | 늘어진 물방울 고리, 재질 넷 | 원형 고리 + 늘어진 꼬리, 금 알(진주 선택지) |
| 성화의 자리 | 기도 화면 배경 한 장 | 홈의 큰 그림, 기도 배경, 갤러리·전체 화면·즐겨찾기·고정 |
| 글꼴 | Noto Sans KR · Noto Serif KR | Cormorant Garamond · Lora · Noto Serif KR |
| 바탕 | 한지(낮) 고정 | 종이색 바탕, 기도 화면만 어두운 스크림 |
| 진입 구조 | 화면 열이 홈에서 갈라짐 | 아래 탭 바 넷 |

이 차이 하나하나를 어떻게 결정하고 어떤 순서로 만들지는 `docs/plan/roadmap-world.md` 에 있다.
