# Handoff: 묵주 (mobile-rosary) — 한지 낮 (Hanji Day)

## Overview
54일 묵주 기도 앱의 화면 열 벌. 이 앱이 파는 것은 "오늘 한 번 기도"가 아니라 **하나의 지향을 54일 동안 바쳐 완주하는 것**이다. 홈은 오늘의 신비가 아니라 **여정 목록**이고, 카드를 한 번 탭하면 곧바로 어제 멈춘 자리에서 기도가 이어진다.

근거 문서: `GeonwooKim-fitogether/atelier` 리포의 `idea/mobile-rosary/` — PRD 제3판(`06-prd.md`), 디자인 시스템(`06-design-system.md`), 화면 명세(`06-screen-spec.md`), 화면 지도(`06-screen-map.md`). 구현 전에 PRD를 함께 읽을 것.

## About the Design Files
이 폴더의 `screens-day.html`은 **HTML로 만든 디자인 참조물**이다. 의도한 모양과 배치를 보여주는 시안이며, 그대로 가져다 쓰는 프로덕션 코드가 아니다. 할 일은 **이 화면들을 대상 코드베이스의 기존 환경에서 다시 만드는 것**이다 — React Native / Flutter / SwiftUI / Kotlin 등 이미 쓰는 프레임워크와 그 관례·라이브러리를 따른다. 아직 환경이 없다면, 이 앱에 가장 맞는 프레임워크를 골라 거기서 구현한다.

브라우저로 `screens-day.html`을 열면 열 화면이 실제 크기(390 × 844)로 나란히 렌더된다. CSS 값은 개발자 도구로 직접 읽어도 되고, 아래 표에 정리된 값을 써도 된다.

## Fidelity
**High-fidelity.** 색·타이포·간격·터치 영역이 모두 확정값이다. 픽셀 단위로 다시 만들되, 스크롤·입력·키보드·햅틱 같은 플랫폼 동작은 그 플랫폼의 표준 컴포넌트를 쓴다.

두 가지 예외:
- **성화 이미지는 목업 자산**이다. PRD D-1(저작권)이 미확정이므로 최종 이미지로 교체될 수 있다. 이미지는 교체 가능한 슬롯으로 구현할 것.
- **묵주 그림**은 SVG로 그렸다. 현재 단의 알 열 개와 큰 알만 실제 크기로 그리고, 나머지 고리는 얇은 실선으로 암시한다(59알을 모두 8% 크기로 그릴 수 없기 때문). 이 타협은 제품팀 확인이 필요하다.

## 이 벌의 정체성
전례서·기도서의 조판을 그대로 가져온 벌. 한지빛 바탕(#EDE7D8)에 먹빛 잉크, 구역을 나누는 것은 카드가 아니라 **얇은 괘선**(1px rgba(31,37,48,.16))이다. 라벨은 10.5px에 letter-spacing .24em으로 넓게 벌린다. 성화는 배경으로 깔지 않고 **고정 높이 도판**(96×124 썸네일, 148–340px 띠)으로 얹는다 — 그래서 글자 길이가 달라져도 그림이 잘리지 않는다. 강조는 치자-d(#82600F) 하나. 라디우스 0, 그림자 0. 20–35 세대와 시니어를 함께 받는 쪽.

### 6. B 기도 — 실제 기도 화면
가장 중요한 화면. 지켜야 할 규칙:
- **화면 안에 고르는 조작이 0개**(§9-23). 신비·단·판본을 여기서 바꿀 수 없다.
- **진행은 자동**. 받는 사이가 끝나면 다음 단계로 넘어간다(FR-12) — **넘기는 단추가 없다**. 하루는 77단계(시작 7 + 각 단 14 × 5).
- **나가는 길은 둘뿐**: `잠시 멈춤`("자리가 남습니다") · `여기서 끝내기`("오늘 처음부터"). 각 80px 이상.
- **현재 알은 화면 너비의 8% 이상**(FR-26) = 390 기준 최소 31.2px. 현재 구현 32–34px.
- **알 배치는 등호장(equal arc length)** 이어야 한다. 등각으로 배치하면 납작한 타원에서 끝쪽 알이 뭉친다 — 실제로 한 번 그렇게 만들었다가 고쳤다. 중심 간 거리 ≥ 알 지름.
- **알의 숨 애니메이션**: `@keyframes bre` — 0%/100% opacity .42 scale(1), 50% opacity 1 scale(1.12), 4초 ease-in-out 무한. SVG `<circle>`에 걸 때는 `transform-box:fill-box; transform-origin:center`가 **반드시** 필요하다(없으면 뷰박스 원점 기준으로 커져서 알이 실 밖으로 튄다).
- **기도문 영역은 고정 높이 + `overflow:hidden`**(FR-24: 글자 길이가 달라져도 그림이 잘리거나 배치가 흔들리지 않는다). 이 벌에서는 210px.
- **레이아웃**: 머리 괘선(지향·일째 / 제3단·성모송) → **148px 성화 도판**(06_Side_Jesus, flex:none) → 묵주 SVG 영역(flex:1, min-height:0, overflow:hidden, 340×245) → 기도문 210px(위 괘선) → 나가는 길 둘(각 flex:1, 82px, 외곽선).
- **문안 예**: 앞 구절 "은총이 가득하신 마리아님, 기뻐하소서. 주님께서 함께 계시니" / 받는 구절 "여인 중에 복되시며 태중의 아들 예수님 또한 복되십니다."(강조색)

## Interactions & Behavior
- **홈 → 기도**: 여정 카드 탭 한 번(중간 화면 없음). 어제 멈춘 단계에서 재개.
- **기도 진행**: 자동. 낭송 방식이 `교대로`면 앞 구절은 음성이 읽고, 받는 구절 구간이 끝나면 다음 단계로 자동 전환. `소리 없이`면 탭으로 진행.
- **알 전환**: 현재 알 4초 호흡(위 `bre`). 단이 바뀔 때는 조용한 크로스페이드만 — 튀거나 미끄러지는 모션 없음.
- **잠시 멈춤**: 자리를 남기고 나간다. **여기서 끝내기**: 오늘 몫을 버리고 처음부터.
- **오프라인**: 기도는 오프라인에서 되어야 한다. 조 배정을 못 받으면 어제와 같은 단(§8). ⚠ **조 여정 첫날에 연결이 없으면 어제가 없다 — PRD 공백.**
- **금지**: 붉은 경고색, 축하 애니메이션·문구, 배지, 연속 기록 압박("streak를 잃었습니다" 류).

## PRD 제3판에서 확정이 필요한 것 (구현 전)
1. **화면 수 불일치** — §5-1은 "시트 여섯", §10은 "시트 일곱"(S7 포함 여부). 시트 번호가 S2부터 시작한다.
2. **초대 코드 입력 화면이 무소속** — 흐름도에는 있고 화면표에는 행이 없다. §5-3의 "어느 화면에도 없는 FR이 0개" 게이트와 충돌.
3. **조 여정의 진척 정의** — 다섯 중 셋만 바친 날을 며칠째로 셀지 규칙 없음.
4. **조 오프라인 첫날** — "배정을 못 받으면 어제와 같은 단"인데 첫날에는 어제가 없다.
5. **FR-45 로그아웃 데이터 손실** — 오프라인에서 못 올린 오늘 자리의 처리가 예외 표에 없다.
6. 작은 것 둘 — FR-38 음량 버튼은 §11-3에서 iOS 거절 가능성이 높다고 적혀 있어 FR 본문과 상충(Android V1.5로 미루는 편이 명확). §6 접근성 "터치 영역 최소 80픽셀"은 iOS 44pt ≈ 88px과 어긋난다.
