## 누적

### 2026-08-26 — 티어 판정에 "전담자 유무 확인"이 없다
- **증상**: CEO 브리프 제작을 메인 세션이 직접(T0) 처리했는데, 문서 정제 전담 에이전트(doc-clarifier)가 있는데도 그것을 확인하는 절차가 판돈 규칙에 없어 전담자가 우회됐다. 결과물은 좋았으나 전담자의 규약이 적용됐는지 아무도 보증하지 못한다.
- **제안**: 판돈 규칙의 티어 판정 앞에 "이 일의 전담 에이전트·스킬이 이미 있는가"를 먼저 확인하는 한 줄 추가.
- **일반화**: 가능 — 전담자가 늘수록 어느 저장소에서든 같은 우회가 생긴다. (사례 1건이므로 규칙 격상은 보류, 규약대로 기록만.)
- **처리 (2026-08-26)**: 수확 → **보류**. 재검토 트리거는 동종 우회 1건 추가 관측(누적 2건).

### 2026-08-26 — 동기화 봇 자신의 버전 드리프트를 재는 장치가 없다
- **증상**: career는 스킬만 내려받는 옛 봇, Geonwoo-LLM-Wiki는 존재하지 않는 경로를 바라보며 9회 연속 실패한 화석 봇이었는데, 수동 전파를 시도하기 전까지 아무도 몰랐다. `.github/workflows/`는 동기화되지 않으므로 이 드리프트는 구조적으로 재발한다.
- **제안**: 자산 그래프 검사(또는 주기 스윕)에 "하위 저장소의 sync-skills.yml이 창고 판과 같은가" 대조 한 줄 추가.
- **일반화**: 가능 — 봇이 있는 모든 하위 저장소가 같은 위험을 진다.
- **처리 (2026-08-26)**: 수확 → 추가검토 → 대표 승인(옵션 B). 동기화 봇이 실행 때마다 자기 파일을 창고 판과 대조해 다르면 GitHub 경고를 남기도록 반영했다. 아무것도 막지 않고 알리기만 한다.

### 2026-08-26 — 워크플로 YAML을 파싱 검증 없이 커밋해 5회 연속 조용히 실패했다
- **증상**: `asset-graph.yml`의 스텝 이름에 따옴표 없이 콜론이 들어가(`name: 그래프 정합 검사 (창고: README 배선 포함)`) GitHub가 파일을 파싱하지 못했다. 실행은 0초·잡 0개로 끝나 5회 모두 실패했고, 정작 검사기는 지역에서 통과하고 있어 "검사가 돌아 통과했다"와 "검사가 아예 안 돌았다"가 보고에서 구분되지 않았다.
- **제안**: 워크플로 파일을 커밋하기 전에 YAML 파싱을 한 번 돌린다(`python3 -c "import yaml;yaml.safe_load(open(f))"` 한 줄). 나아가 자산 그래프 검사에 "워크플로 YAML이 파싱되는가" 한 축을 더할 수 있다.
- **일반화**: 가능 — 워크플로를 추가하는 모든 저장소가 같은 실수를 할 수 있고, 실패가 조용해서 더 위험하다.
- **처리 (2026-08-26)**: 수확 → 승인 후보 → 대표 승인(옵션 A). 자산 그래프 검사에 네 번째 축으로 반영했다(`.github/workflows/*.yml` 파싱 검증). 이 축이 어제의 실제 버그를 재현 시험에서 잡는 것을 확인했다.

### 2026-08-28 — 결정 카드가 기본값을 갖고도 차단기처럼 운용됐다
- **증상**: 규칙 개정 세션 하루에 결정 카드 7장이 연속 상신됐다. 전부 "무응답 시 기본 행동"이 있었는데도 답을 기다리며 진행을 멈췄고, 대표가 "사용성이 복잡해졌다 — 결정을 하나씩 선택하게 만든다"고 직접 지적했다.
- **제안**: 기본값 있는 카드는 추천대로 진행하며 기한부 공지로 올린다. 위임 원장에 "추천+기본값+되돌리기 쉬움 결정 전부" 범주를 등재한다 (등재는 규칙대로 사람 승인 대기).
- **일반화**: 일반 — 모든 저장소의 상신이 같은 서식을 쓰므로 같은 오운용이 재현된다.

### 2026-08-28 — 사람에게 셸 명령 실행을 전제 설명 없이 부탁했다
- **증상**: 브랜치 정리 스크립트를 "bash로 실행해 달라"고 부탁하며 실행 장소·운영체제 전제를 밝히지 않아, 대표가 "PowerShell에서 하라는 것인가"부터 되물었다. 결정 카드에는 번역 관문이 생겼지만 행동 부탁에는 관문이 없었다.
- **제안**: 기계 우선 검사(버튼으로 만들 수 있으면 부탁하지 않는다) + 부탁 서식 + 부탁 리트머스 3문항 — communication 규칙 8로 같은 날 격상(대표가 "수도 없이 이야기했다"고 직접 지적 = 2건 이상 누적 기준 충족).
- **일반화**: 일반 — 모든 저장소의 세션이 사람에게 행동을 부탁한다.

### 2026-09-08 — 한 작업 폴더에서 병렬로 도는 세션이 남의 미완성 파일을 자기 커밋에 쓸어 담았다
- **증상**: 문서만 고치던 세션의 커밋(`1e7dd6c`)에 같은 시각 다른 세션이 쓰고 있던 `package.json`·`tsconfig.json`이 함께 들어갔다. 커밋 메시지는 문서 개정만 말하고 있어, 나중에 이력을 읽는 사람은 그 두 파일이 왜 거기 있는지 알 수 없다. 전면 스테이징(`git add -A`)이 원인이고 아무 오류도 나지 않았다.
- **제안**: 병렬 세션이 도는 저장소에서는 커밋 전에 자기가 만든 경로만 명시해 스테이징한다(`git add <경로>`). 또는 커밋 직전 `git status`에 자기 작업 밖의 파일이 있으면 멈추고 확인한다.
- **일반화**: 일반 — 여러 에이전트를 한 작업 폴더에서 병렬로 돌리는 모든 저장소가 같은 위험을 진다.

### 2026-09-08 — `expo install` 이 프록시에 막혀 SDK 호환 버전을 조회하지 못한다
- **증상**: M1 에서 기기 기능 꾸러미(소리·진동·센서·저장)를 더하려고 `npx expo install` 을 불렀는데 `HTTP Proxy Network Error: Forbidden` 으로 실패했다. 이 명령은 Expo API 에 물어 SDK 에 맞는 버전을 골라 주는 것이라, 막히면 어떤 버전이 SDK 57 과 맞는지 알 방법이 사라진다. `npm install` 은 같은 프록시에서 정상 동작한다.
- **제안**: 이 환경의 사실로 문서에 적어 두고(작업 지시서의 "환경의 사실" 표), 꾸러미를 더할 때는 `npm view <꾸러미> version` 으로 판을 확인해 `npm install <꾸러미>@<판>` 으로 고정해 넣는다. 그 뒤 타입 검사·단위 시험·웹 빌드 셋으로 맞는지 확인한다.
- **일반화**: 일반 — Expo 를 쓰는 저장소가 이 실행 환경에서 모두 같은 벽을 만난다. (사례 1건이므로 규칙 격상은 보류, 규약대로 기록만.)
