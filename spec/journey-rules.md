# 여정 규칙 — 프레임워크 무관 도메인 스펙

> 한 줄 요지: **이 문서는 PRD(`docs/product/06-prd.md`)와 화면 명세(`docs/product/06-screen-spec.md`)에 흩어져 있는 "기계가 계산해야 하는 규칙"을 한 곳에 모아 적은 것이다.** 새 규칙을 만들지 않는다 — 출처 FR 번호를 매 항목에 단다. PRD에 없어서 정해야 하는 것은 규칙으로 쓰지 않고 `decisions.md` 결정 큐 번호를 가리킨다.

함께 읽는 파일: [`prayer-sequence.json`](./prayer-sequence.json)(77단계) · [`mysteries.json`](./mysteries.json)(신비와 순환 규칙) · [`prayers.ko.json`](./prayers.ko.json)(기도문, 판본 미확정).

## 1. 여정(journey)의 형식 셋 — PRD §1-4 · FR-33

| 형식 키 | 이름 | 길이 | 완료 예정일 | 오늘의 신비 규칙 |
|---|---|---|---|---|
| `fiftyfour` | 54일 기도 (기본값) | 54일 | 시작일 + 53일 | 54일 순환 (`mysteries.json` → `rules.fiftyfour`) |
| `novena9` | 9일 기도 | 9일 | 시작일 + 8일 | 요일 규칙 |
| `daily` | 날마다 | 끝 없음 | 없음 (화면에 이 줄이 없다) | 요일 규칙 |

- **며칠째(dayIndex)는 달력으로 센다.** `dayIndex = (오늘 날짜 − 시작일) + 1`, 기기 현지 날짜 기준. 하루를 건너뛰어도 dayIndex는 흘러가고 그날 칸은 비어 있는 채로 남는다(FR-35). 처음부터 다시 하라고 강요하지 않는다.
- **청원과 감사(54일만).** `dayIndex 1~27 = 청원`, `28~54 = 감사`(FR-35). 화면 표기는 `{N}일째 · 청원` / `{N}일째 · 감사`.
- 시작일이 미래인 여정은 `dayIndex ≤ 0`이며 홈에서 흐린 카드로 보이고 기도로 들어가지 않는다(FR-36, 06-e 결함 8).
- 시작일이 과거여도 허용한다. 지난 날은 빈 칸으로 만들어진다(PRD §8).
- 여정에는 **기도문 판본**이 고정된다(FR-34). 설정의 기본 판본을 바꿔도 진행 중 여정의 문구는 바뀌지 않는다.

## 2. 하루의 기도 — 77단계 · FR-10

`prayer-sequence.json`이 정본이다. 시작 기도 7단계(성호경 · 사도신경 · 주님의 기도 · 성모송 3 · 영광송) + 각 단 14단계(신비 선포 · 주님의 기도 · 성모송 10 · 영광송 · 구원을 비는 기도) × 5 = 77. 마침 기도는 넣지 않는다(D-3).

**조 기도(함께 바치기)의 하루는 내 몫 한 단**이다(FR-40). 14단계인지, 시작 기도 7단계를 앞에 붙인 21단계인지 PRD가 명시하지 않았다 — `decisions.md` 결정 큐 Q-03 참조(기본값: 내 단 14단계만. 완주 화면 통계도 "성모송 10").

## 3. 자리 저장과 이어가기 — FR-02 · FR-03 · FR-17 · FR-18

| 규칙 | 내용 | 출처 |
|---|---|---|
| 저장 시점 | **알을 넘길 때마다** 저장한다. 기기에 먼저, 계정에는 연결될 때 올린다 | FR-17 |
| 저장 내용 | 여정 ID · 단계 인덱스(0~76) · 몇 단 · 몇 번째 알 · **어느 신비였는지** · 멈춘 시각 | FR-03 · PRD §7 |
| 이어가기 | 저장된 자리가 있으면 그 자리부터, **저장된 신비**로 진행한다(날짜가 바뀌어 오늘의 신비가 달라졌어도) | FR-02 · FR-03 |
| 잠시 멈춤 | 자리를 남기고 홈으로 | FR-18 |
| 여기서 끝내기 | 오늘 자리를 지우고 홈으로 | FR-18 |
| 오늘 처음부터 | 여정 상세에서 S3 확인 뒤 자리를 지우고 처음부터 | FR-18 |
| 두 기기 충돌 | **더 앞선 자리**를 남긴다(기도를 잃지 않는 쪽) | PRD §8 |
| 손상된 자리 | 버리고 오늘 처음부터 시작할 수 있게 둔다 | PRD §8 |
| 앱 이탈(전화 등) | 자리 저장 후 **멈춤 상태**. 돌아오면 "이어서 바치기 / 홈으로" | 06-d 화면 B |

## 4. 낭송 방식과 받는 사이 — FR-06 · FR-11 · FR-12 · FR-13 · FR-07

낭송 방식 셋: `full`(전부 읽기) · `alternate`(교대, 기본값) · `silent`(읽지 않기).

| 방식 | 앱이 읽는 것 | 사용자 몫 글자수 L | 진동 |
|---|---|---|---|
| `alternate` | 앞 절(a)만 | 뒷 절(b)의 글자수 | 없음(소리가 있다) |
| `full` | 앞 절 + 뒷 절 | 0 (짧은 숨 하나) | 없음 |
| `silent` | 없음 | 앞 절 + 뒷 절 글자수 | 알 넘어감 1회 · 단 전환 3회(FR-14) |

**받는 사이 공식**(06-d 화면 B 비화면 채널): `(900ms + L × 132ms) ÷ 속도계수`. 속도계수는 느리게 0.75 · 보통 1 · 빠르게 1.35(FR-07). 신비 선포 뒤는 고정 2200ms. 음성 속도(TTS rate)는 0.92.

기기에 한국어 음성이 없으면 `silent`로 진행하고 사용자 몫에 앞 절 글자수를 더한다(PRD §8).

## 5. 진동 사전 — 06-d 화면 B

| 사건 | 패턴 (ms) |
|---|---|
| 알 넘어감 (`silent`일 때) | 18 |
| 단 전환 | 28 · 60 · 28 · 60 · 28 |
| 읽지 않기를 설정에서 켤 때 | 20 · 50 · 20 |
| 하루 완주 | 200 (FR-27) |

진동을 지원하지 않는 기기는 사이만으로 진행하고 오류를 내지 않는다.

## 6. 손 없이 조작 — FR-38 · PRD §11-3

설정에서 켠 경우에만. **한 번의 조작은 한 알**만 움직인다(배속·건너뛰기가 아니다, §9).

| 입력 | 동작 | 플랫폼 |
|---|---|---|
| 폰 흔들기 1회 | 다음 알 (사이가 남아도 즉시) | iOS · Android |
| 이어폰 재생/일시정지 | 잠시 멈춤 / 이어서 | iOS · Android |
| 이어폰 다음 / 이전 | 다음 알 / 이전 알 | iOS · Android |
| 음량 위/아래 | 다음 알 / 이전 알 | **V1에서 쓰지 않는다** — iOS 심사 지침 2.5.9. Android 도입 여부는 `decisions.md` Q-06a |

되돌아간 알은 자리 저장이 그 알로 되돌아간다. 가속도 센서가 없는 기기는 설정에서 흔들기 항목을 감춘다.

## 7. 함께 바치기(조) — FR-40 · FR-44

- 정원 다섯. 바람과 형식을 공유한다. 초대 코드(여섯 자리, 대소문자 구분 없음)는 **서버가 발급**하므로 조 만들기와 합류는 연결이 있을 때만 가능하다(06-e 결함 10).
- 날마다 조원에게 제1단~제5단을 하나씩 배정한다. 조원이 다섯이 안 되면 남은 단은 있는 사람들에게 **돌아가며** 배정된다. 조원이 나가면 남은 사람에게 다시 배정된다.
- 오늘 배정을 못 받았으면(연결 없음) **어제와 같은 단**을 바치고 연결되면 맞춘다(PRD §8). 첫날에는 어제가 없다 — `decisions.md` Q-04.
- 다섯 중 몇 단이 바쳐졌는지는 홈 카드와 완주 화면에 "다섯 중 K"로만 보이고, 누가 안 했는지는 적지 않는다. 그날을 조 여정의 진척으로 어떻게 세는지는 PRD에 없다 — `decisions.md` Q-03.
- 조원 이름은 로그인 계정의 표시 이름을 쓰고 조 안에서만 보인다(FR-44). 공개 목록·검색·추천은 없다.

## 8. 전례 시기 — FR-25 · 06-b §2-3

부 강조색 슬롯 `--season`은 전례 시기에 따라 바뀐다: 대림·사순 = 자색 · 연중 = 녹색(쑥빛) · 부활·성탄·성모 축일 = 백색 · 성령강림·수난·순교 = 홍색. **시기 계산 규칙(부활 날짜 산출, 대림 시작일 등)은 PRD가 정하지 않았다.** 프로토타입 v4는 월(月)로 근사했다. 정확한 전례력 계산은 구현 시 정해야 하며 `decisions.md` Q-10에 올려 두었다.

## 9. 이 문서가 정하지 않는 것

기도문의 공식 판본(D-4), 성화 출처(D-1), 밤/낮 기본값(D-2), 위 Q-번호 항목 전부. 이것들은 `decisions.md`가 갖는다.
